# 親機校正導線修正の書込み・実機確認

## 前提
- ユーザーから書込み・動作確認の指示を受けて実施。
- 親機USB A444A41EE9334705 / COM6 / P_MAIN、子機USB A521D21EB1DCFB44 / COM3 / C_MAINを現在の応答と照合。
- 今回の修正は親機Web画面。親機のみ書込み、子機は状態読取りのみ。Wi-Fi切替・実機Web自動操作・SDフォーマット・既存ログ削除・校正の再実施や上書きなし。Spresenseへの書込みなし。

## 実施
- 前回004で検証した親機ファームウェアをscripts/flash.py parentで書込み。個体番号・応答・測距停止・記録停止を確認後、フラッシュ100%照合とアプリ再起動に成功。
- 書込み後にUSB状態を複数回取得。初回は親機の応答を取得できず、ポートの開き直し・DTR切替後も一時無応答。後続照会で復帰。原因は断定しない。
- 親機のUSB X/qで測距・記録停止、STOPPED確認後にsで準備記録再開を試験。これはWebボタンの実機試験ではなく、同じ記録開始処理のUSB試験。
- 再開後15秒の待機では応答なし。その後の複数照会でも一時取得できず、最後の照会で新規ファイルと行数進行を確認。長い無応答期間を残る問題として扱い、即時復帰の合格とはしない。

## 実測・確認結果
- 親機の書込みSUCCESS。バイナリSHA256等はraw内verification.json。
- 起動後の親機記録0→9行、SDエラー0。その後STOPPEDを確認。再開後はP_MAIN_TIME_POSITION_00070.bin、最後の約20秒の照会で25→44行、SDエラー0、測距停止。
- 子機は書込み前から最後までSTOPPED。保存行数26283で不変、通信エラー累計2で期間内増加なし。親子とも相対同期成立。ただし精度合格の意味ではない。
- 親機Spresense：書込み前は通信途絶だったが、後続の実機照会で通信復帰。校正番号3、calibration_applied=true、記録中、SD正常、SDエラー0。pps_paired=true、imu_time_ready=trueを確認。
- 親機磁気：P_MAIN_MAGCAL_00001.bin復元、enabled=true。親機校正セット番号3・calibrations_match=true。
- 機体軸変換はg=0、r=0。収録番号c=2は存在するが軸変換保存の証拠ではない。今回のカメラ動作収録k=0。個別校正は適用済みであり、次の作業は初回機体軸合わせ収録。
- 最終実機テレメトリを本番UI関数へ入力するオフライン試験で、親機・Spresenseの状態カードが赤くならず「検出異常なし」、準備条件確認済みの案内となることを確認。Spresenseの応答期限切れ履歴24は保持されており、増加していない履歴だけでは赤くならない。
- 生ログ・失敗時ログはreports/raw/2026-10-27_005_parent_workflow_deploy。before/after/retry/final/settled/final_retry、parent_controls、upload_parent、telemetry_ui_checkを保持。

## 未検証・残る問題

- 実機Web画面のクリック・表示はユーザー確認。Wi-Fi切替やtest_web_device.py/test_web_controls.pyは実行していない。公開GitHub Pagesは更新していない。
