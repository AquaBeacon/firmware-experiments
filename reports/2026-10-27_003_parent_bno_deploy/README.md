# 親機へのBNO校正案内修正版の配備

## 前提

- 2026-10-27 JST。ユーザーから「親機も更新して」と指示。子機は直前の002レポートで更新済み。
- 対象は親機USB A444A41EE9334705 / COM6、P_MAIN応答で識別。子機USB A521D21EB1DCFB44 / COM3、C_MAIN応答も読取り確認する。
- ピン・配線の変更なし。親機GP6は外付けGNSS PPS入力、GP7–D03半二重、Spresense D02入力専用を維持する。親機温度・水圧・LCDは検証対象外。
- PCのWi-Fi切替と実機Web自動操作、SDフォーマット・既存ログ削除、校正開始・校正保存は行わない。

## 配備内容と実施

- 002でホスト試験とparent/child100ビルドに合格した修正を親機へ反映。機体内Webにジャイロ静止進捗と低判定時の案内を追加し、旧子機の表示にも対応する。
- 書込み前にUSB個体番号とP_MAINを照合し、測距停止・親機SD停止を確認してparentを書き込む。子機へ書込みや記録の開始/停止指示は行わない。
- 書込み前の親子記録はともにSTOPPED。子機の停止状態を維持する。Spresenseは更新前からlink_fresh=falseのため、現在の補正適用・保存状態は判定しない。
- 書込み後はUSBを再照合し、親子状態と親機記録の進行を読取り確認する。起動時の通常動作で親機は新しいファイルへ記録を開始する。

## 結果

- scripts/flash.py parentはSUCCESS。親機個体番号とP_MAIN応答の一致、安全停止、フラッシュ100%照合、アプリ再起動を確認。
- 最初の約12秒は親機USB出力を取得できなかった。COM6を閉じて再度開き、DTRを切り替えて再照会するとP_MAIN応答を11件取得できた。原因は断定しない。生ログは初回失敗分も保持。
- 最終6秒の照会で親機SD保存49→55行、sd_reason=NONE、SDエラー0。測距は停止中。子機は書込み前のSTOPPEDを維持し、記録再開指示は送っていない。
- 親子とも相対同期成立、テザー受信経過49/422ms。親機通信エラー累計0→0、子機2→2で期間内増加なし。子機は更新前の累計1から親機再起動後の観測までに1増加しているが、原因や同期精度は未検証。
- 埋込みHTMLに新しい静止進捗処理が含まれることを確認。実機ブラウザの表示操作はユーザー確認のため未実施。
- Spresenseは更新前後ともlink_fresh=false。再起動後の校正番号0/applied=falseは未取得時の初期値であり、SD内補正の消去や再無効化を確認したものではない。校正開始/保存/解除は実行していない。
- バイナリのSHA256と確認値はevidence/verification.json。生ログはreports/raw/2026-10-27_003_parent_bno_deployへ保存。
