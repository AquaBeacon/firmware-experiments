# 子機BNO085の静止校正実機確認

## 前提
- ユーザーが機体を静止させ、「校正できることを確認」と指示。
- 親機USB A444A41EE9334705/COM6/P_MAIN、子機A521D21EB1DCFB44/COM3/C_MAINを応答と照合。
- 既存USB hは全体の更新情報のみで、精度状態0〜3と静止進捗を返さない。親機STAは非接続。PCのWi-Fi切替・実機Web操作を行わず確認するため、子機USBの校正診断を追加。

## 実施
- `@BNO 13..16`（開始・状態・保存・終了、改行区切り）を既存の制御へ接続。コア1の校正処理、記録停止要求、保存条件、保存応答のSD履歴は既存処理を共有。受付と完了を分け、USB処理中はテザー操作の取り出しを待つ。
- USB番号・C_MAIN応答・記録停止を再確認してchild100を書込み。フラッシュ照合成功。親機とSpresenseには今回書込みなし。
- 子機記録停止後、状態照会→校正開始→約45秒の状態照会。ユーザーが静止中と申告。机上での実際の振動・角速度値は別途未測定。
- 保存可能時だけ保存する試験としたが、一度も条件成立せず、保存命令は送っていない。試験後にCAL_END成功・active=0を確認。
- 入力パーサーを固定形式にして巨大整数の変換を避ける最終修正をビルド・再書込み。

## 実測
- 校正開始：op13/error0/active1。開始直後の加速度・磁気-1は新セッションの初期未取得。
- 校正中のop14応答22件、最初から最後まで44.464秒。
- ジャイロgは全22件で0。子機内で500ms未満の新しいイベントがあるため0が返っており、更新停止を示す-1ではない。
- 加速度は初期未取得後2。磁気は1と2を往復。
- gs最大0ms、gr=0、ready=0、err=0。現在の条件ではジャイロ精度状態1以上を要求するため、g=0で静止判定は進まない。小さい角速度が続いたことを確認した結果ではない。
- CAL_SAVE送信0回。CAL_END/error0/active0/saved0を確認。
- **静止しただけで校正・保存可能になることは確認できず、ユーザーの症状を再現した。** IMU更新正常と校正成立は別であり、前者だけを根拠に後者を合格にしない。
