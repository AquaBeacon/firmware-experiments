# 子機SD保存の取りこぼし対策

## 前提
- ユーザー指示：子機のSD保存取りこぼしを解決する。
- USB番号A521D21EB1DCFB44 / COM3とC_MAIN応答を照合。対象は子機100Hz IMU＋全BNOイベント。既存ログ/校正値を保持。
- PCのWi-Fi変更、実機Web操作、SDフォーマット/削除、隣接元リポジトリの変更なし。ピン・SPIクロック4MHz・IMUレートを維持。親機/Spresenseは書込みしない。

## 調査と変更
- 初期実装はSPIを1byteずつ完了待ちし、さらに短いIMU/BNO記録がSdFatの共通セクタキャッシュを頻繁に切り替える。sdTickの共通4ms処理予算もあり、BNOキューが排出されず取りこぼしが継続していた。
- まずSPIを最大8byteのFIFOへ並行投入し、受信も全て排出するよう修正。転送20ms・初期化累積期限と障害後の停止を維持。これ単独では取りこぼしが残った。
- 次にIMU/BNOイベントへ独立した4096byte RAMバッファー（合計8192byte）を追加。32byteヘッダー後/同期後の端数を考慮し、通常排出の末尾を512byte境界に揃える。ログのバイト列、CRC、時刻、連番を保持。
- 毎秒同期、安全停止、復旧診断前に端数排出→syncを実行し、成功後だけdurable_rowsを更新。失敗後に同じバッファーを黙って再送しない。新規マウントで初期化し、別ログへ旧データを混ぜない。
- README/docs/spec.mdを更新。新規docsファイルはない。

## ソフトウェア検証
- 既存P_MAIN_experimentのvenvからscripts/test_host.py全体PASS。ログhost_final.txt。
- セクタバッファー：異なる長さの交互ストリーム、レコード分割、周期同期の端数、全バイト一致、書込み失敗後の停止、新規ファイルでの初期化を検証。
- 実writeBinary/flushSdWriteBuffers/finishStop：端数保存後のclose、記録数とCRC一致、durable_rowsの更新、端数失敗時にSTOP_SYNC_FAILEDを検証。
- SPIのFIFO上限8、送信順・受信順、全受信排出、TX/RX停滞、累積期限、失敗後の初期化を検証。
- parent/child100ビルドSUCCESS。識別・安全停止後に子機へ書込み、全量Flash照合OK。FIFO単独版とまとめ書き版の書込みログをrawに保存。

## 実測：変更前と段階比較
- 変更前：9.088523秒でIMU保存597件、取りこぼし2931件増加（うちraw_dropped2618）、SDエラー増加0。
- FIFO単独：34.215244秒でIMU保存2735件、BNO保存2659件、取りこぼし8508件増加（うちraw_dropped8342）。FIFO最適化だけでは不足。
- まとめ書き：38.700948秒でIMU保存3869件、BNO保存13595件、取りこぼし/IMU欠落/SDエラーの増加0。起動後の累積取りこぼしも0。BNO校正保存履歴番号3を保持。
