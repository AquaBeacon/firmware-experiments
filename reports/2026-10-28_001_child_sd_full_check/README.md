# 子機SDカード全ファイル保存検査（2026-10-28）

## 前提
- ユーザー依頼：子機SDカードから、保存がうまくいっているか全て確認する。
- 対象はD:、FAT32、リムーバブル媒体。機体データ575ファイルとWindows管理ファイル2件の計577件、6,185,713,623byteを再帰列挙し、全ファイルを読取り。
- 子機AQBINのrole=2と、校正・姿勢収録の機体ID A521D21EB1DCFB44を確認。USB操作・ファーム書込みなし。
- SDへの書込み・修復・削除・フォーマットなし。Wi-Fi切替・実機Web操作なし。ファイル名の番号はランダムな開始番号を含むため、大小を収録日時として扱わない。

## 実施
- 各ファイルをストリーミング読取りしSHA256を保存。列挙/読取り失敗なし、検査中のサイズ・更新日時の変化なし。
- AQBIN 146件：ヘッダーと全レコードのCRC、フレーム長、末尾、IMU index/100Hz時刻グリッド、BNOセンサー別連番・時刻、HEALTHカウンターを検査。
- CSV 337件：全50,124,497データ行を走査。機体CSV 156件は全行CRCと列構造を検査。旧ACOUSTIC_RAW CSV 181件はCRC列がないため、列数・数値・グループ内時刻・同期との差分・ADC範囲を検査。
- BNO校正保存履歴4件：112byteのProfile形式としてCRC、世代、機体ID、四元数、時刻変換値の範囲等を検査。通常AQBINとは区別。
- Vxxxxx.BIN 88件：起動時のSD読書き確認ファイル。各512byte、全byteの既知パターンを確認。
- Windows管理ファイル2件：全byte読取りとハッシュのみ。ファームログとしては解析しない。
- IMU/BNO/HEALTHの対応88組は全て存在し、バイナリ形式の組は起動sessionも一致。BODY_CAPTUREの参照ログ/校正履歴の存在とsession一致を確認。
- 既存binary_log、body_alignment、verify_multipath_logを利用。単にCRCが正しいことと、計測データが欠落していないことを分けて判定。

## 実測：保存形式の整合性
- CRC不一致0、バイナリ末尾欠損0、CSV列異常/不正数値/行末欠損0、未識別形式0、ファイル読取り失敗0。
- バイナリは全11,482,693レコードを検査。IMU/BNOセンサー値の非有限値0。HEALTHの未接続温度等に入るnanはセンサー破損とは数えない。
- Vファイル88件とBNO校正保存履歴4件は全て検査通過。
- ヘッダーだけでデータのないログ39件（AQBIN 35件、CSV 4件）。空であること自体は形式破損ではないが、計測実施の証拠にはならない。
- CRCのない音響CSVは構造検査の通過であり、CRCによる内容の完全性保証はできない。

## 実測：欠落・診断履歴

以下は複数項目が同じファイルに重複する。累積エラー履歴を含め、注記対象は計156ファイル。156件のファイル破損という意味ではない。

| 内容 | ファイル数 | 解釈 |
|---|---:|---|
| IMU indexの欠落 | 33 | 一部の100Hzグリッドが記録されていない |
| BNOセンサー連番の不連続 | 41 | 8bit連番の差分。欠落のほかセンサー再初期化等も含み得る |
| BNO source_usの同値/逆行 | 25 | 内部時刻を厳密単調と仮定した解析には注意 |
| HEALTHの累積dropped非ゼロ | 66 | 過去から引き継ぐ値も含む。各ログ内増加と区別する |
| HEALTHの累積imu_gaps非ゼロ | 8 | 同上 |
| HEALTHの累積sd_errors非ゼロ | 3 | 下記3ログ。いずれも当該ログの最初と最後で同値 |
| 音響サンプル欠落を含むファイル | 2 | 10収録中7収録はlossless、3収録は欠落あり |
| 未完了の姿勢収録 | 1 | BODY_CAPTURE_00001の中止記録 |

- SDエラー履歴はC_MAIN_HEALTH_RANGE_00006.csv / 00007.csv / 00025.csv。累積値はそれぞれ1 / 1 / 4で、ログ内の増加はなし。この3件から今回のSD書込み失敗を断定しない。
- IMU欠落が多い例はC_MAIN_IMU_100Hz_42856.bin（1,596,809グリッド）、07059.bin（31,983）、35415.bin（29,771）。記録された行のCRCが正しくても、抜けたグリッドは復元できない。
- 音響欠落はC_MAIN_MULTIPATH_00017.binのshot340と、00022.binのshot337/357。終了マーカーがあってもlosslessとはしない。全10件はBEGINを持つ収録の数で、BEGINなしの不成立ENDのみの試行は別。
- source_us逆行だけではSD保存不良やセンサー故障と断定できない。8bit連番では256件の倍数の欠落を検出できず、連番の一致だけを完全無欠落の保証としない。

- 収録完了mask=31と保存整合性を確認したが、静止・姿勢・磁場条件での解析不合格は変わらない。軸変換のSD保存も未実施。[前回の解析](../2026-10-27_019_child_body_sd_check/README.md)を参照。

## 判定
- カード上で見える全ファイルは読取り可能。検査対象のCRC付きログに形式破損は見つからなかった。
- ただし、過去の全ログを欠落なしとは扱えない。計測中の取りこぼしや音響欠落を含むため、利用時はファイル単位で注記を確認する。
- 今回の軸合わせ区間について、SD保存に起因する新しい欠落は検出されなかった。軸合わせ不合格の静止・姿勢・磁場条件とは分けて扱う。

## 未検証・限界
- chkdsk D:を修復オプションなしで実行。ファイル/フォルダー列挙は完了したが、Access is denied、他プロセスが使用中との警告、終了コード1があるため、FATの完全な正常判定には使わない。修復・アンマウントは実施しない。
- 未割当領域/物理全セクターの読取り、実書込み/容量偽装試験、将来の長時間運用・音響同時負荷は未検証。今回の検査をカード全領域の健全性保証とはしない。
- 正常なレコード境界で電源断し、RAMに残った末尾データが失われた場合は、保存ファイルだけでは全件数を確定できない。HEALTH最終行も周期記録のため最終closeの件数証明にはしない。
- 保存済みBNO履歴は内部DCD保存成功の履歴。内部係数の再読出し一致確認ではない。
- 姿勢/磁気/時刻/距離の絶対精度は未測定。ファームウェアや仕様の変更なしのため、ビルド・ホストテストは未実施。
