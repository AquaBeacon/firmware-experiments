# BNO085ジャイロ受信と静止判定の区別

## 前提
- ユーザー申告：「状態が低下／更新未確認」が続いている。
- 該当文言は子機BNO085の静止確認欄。前回確認した親機Spresenseの補正適用・PPS状態とは別。
- Wi-Fi切替、実機Web自動操作、SD削除・フォーマットは行わない。

## 実施
- 表示コードと子機イベント処理・判定コードを照合。
- gは子機のジャイロ校正精度状態。500ms以内のイベントがあれば0〜3、未受信・古ければ-1。従来UIのc.g<1は0と-1を一緒に「状態が低下／更新未確認」と表示していた。前回値との比較は行っておらず「低下」も未立証。
- 受信、未校正0、校正開始前、静止進捗、静止確認済みを区別する表示へ変更。保存条件は維持。
- 0は受信停止を意味しない。ただし既存判定では精度状態1以上・有限角速度・継続した静止条件を要求するため、0のままでは静止確認を進めない。
- 親子USBを照会したが、どちらの既知個体番号も見つからず、BluetoothのCOM4/COM5のみ。ユーザーへUSB接続を依頼。

## 検証・実測
- scripts/test_console_ui.py PASS：g=-1、0、1、非校正中、静止確認済みの区別と既存テスト。
- pio run -e parent SUCCESS。
- 接続依頼後、子機USB A521D21EB1DCFB44 / COM3 / C_MAINを照合。hによる読取りのみ実施。20件の状態応答すべてでIMU正常フラグが成立し、約10秒で姿勢レポート数82245→83234、IMU欠落累計5→5。IMU正常判定の実装は姿勢・加速度・ジャイロ各最終イベントが3周期以内であることを要求するため、観測時点のジャイロ継続更新の証拠になる。角速度値そのものや校正状態0〜3の直接取得ではない。
- 同観測中CALIBRATINGフラグは0。現時点では校正/機体収録セッション中と報告されていない。終了理由・以前の表示時点の状態は断定しない。
- 親機USBは後から列挙されたが、connectedの10秒照会では応答未取得。Wi-Fi切替やWeb実機操作での回避は行わない。
- 更新した画面は未書込み。子機への校正開始・保存・終了・リセットは行わず、現在状態を保持。
